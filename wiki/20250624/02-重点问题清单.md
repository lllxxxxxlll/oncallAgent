## P0：当前瓶颈 — 卡住开发的问题

### 1. InputKey/OutputKey 的匹配规则

**困惑**：为什么生产代码有时候设 Key，有时候不设？

```go
// 生产代码 knowledge_index_pipeline：不设 Key
_ = g.AddLoaderNode(FileLoader, loader)

// 脚手架代码：必须设 Key
_ = g.AddLoaderNode(FileLoader, loader,
    compose.WithInputKey("document.Source"),
    compose.WithOutputKey("[]*schema.Document"))
```

**要搞清楚**：
- 不设 Key 时 Eino 怎么自动推断？（和 `NewGraph[I, O]` 的泛型有关？）
- 泛型参数 `I` 怎么映射为 START 节点的输入 Key？
- 两个节点输出到同一个 Key 会覆盖还是报错？
- Key 的命名规则是什么？（`"document.Source"` 这种带包路径的名字从哪来的？）

### 3. Lambda 节点的本质和工作方式

**下一步练习**（在 Splitter 后加打印 chunk 数量的节点）：

```go
g.AddLambdaNode("Print", compose.InvokableLambdaWithOption(
    func(ctx context.Context, docs []*schema.Document) ([]*schema.Document, error) {
        fmt.Printf("切分为 %d 个 chunk\n", len(docs))
        return docs, nil
    }),
    compose.WithInputKey("[]*schema.Document"),
    compose.WithOutputKey("[]*schema.Document"),
```

### 6. Eino Graph 的并发模型

- Chat Pipeline 中 RAG 检索和用户输入处理是**并行 goroutine** 还是串行？

**要能说清楚**：
- 类型安全：Go 泛型编译期检查 vs Python 运行时 duck typing

- 团队适配：Go 技术栈团队的首选

### 8. Eino 的错误处理与容错

- Graph 中一个节点出错，整张图直接终止？还是可以 fallback？
- Tool 调用失败后，ReAct Agent 怎么感知并决定重试？
